# Design Authority

## Purpose

This document defines how design decisions are made for this project.

## Authority Hierarchy

### 1. Visual Authority (Highest Priority)

**Source:** Approved Claude Design prototype.

Defines: - Layout - Typography - Spacing - Color palette - Visual
rhythm - Components - Motion - Interaction

**Rule:** Implement faithfully. Improve code, not the design.

------------------------------------------------------------------------

### 2. Content Authority

**Source:** Approved website manuscript.

Rules: - Never invent achievements. - Never exaggerate impact. - Never
replace scholarly writing with marketing language. - Use TODOs instead
of speculative text.

Voice: - Scholarly - Precise - Evidence-based - International -
Restrained

------------------------------------------------------------------------

### 3. Information Architecture

**Source:** PROJECT.md, ROADMAP.md and approved planning documents.

Defines: - Navigation - Page hierarchy - Section order - Project
grouping

Structure does **not** override design or content.

------------------------------------------------------------------------

### 4. Technical Authority

Technology serves the design.

Prioritize: - Accessibility - Performance - Maintainability - Clean
components

Never simplify the design for implementation convenience.

------------------------------------------------------------------------

## Conflict Resolution

Visual Design → Content → Information Architecture → Technical
Convenience

If a major design change is required, explain the trade-offs before
implementing it.
